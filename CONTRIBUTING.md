# Contributing

Thank you for your interest in contributing to a MIDDAG repository. This guide applies to every public repository of MIDDAG that has no contributing guide of its own.

## Before you start

- **Security issues:** do not open an issue. Follow the [security policy](SECURITY.md).
- **Bugs and feature requests:** open an issue with the matching form, so the change can be discussed before you write code.
- **Conduct:** every interaction follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Pull requests

1. Fork the repository and create a branch from `main`.
2. Keep each pull request focused on one change.
3. Write commit messages in the [Conventional Commits](https://www.conventionalcommits.org) format, for example `fix: handle empty course list`. Do not add `Co-Authored-By` trailers.
4. Run the checks the repository documents (tests, linters) before you open the pull request.
5. Open the pull request against `main` and fill in the template.

Changes land on `main` only through reviewed pull requests, merged with a merge commit.

# Como contribuir

Obrigado pelo interesse em contribuir com um repositório da MIDDAG. Este guia vale para todo repositório público da MIDDAG que não tenha guia de contribuição próprio.

## Antes de começar

- **Falhas de segurança:** não abra issue. Siga a [política de segurança](SECURITY.md).
- **Bugs e pedidos de melhoria:** abra uma issue com o formulário correspondente, para discutir a mudança antes de escrever código.
- **Conduta:** toda interação segue o [Código de Conduta](CODE_OF_CONDUCT.md).

## Pull requests

1. Faça um fork do repositório e crie um branch a partir de `main`.
2. Mantenha cada pull request focado em uma mudança.
3. Escreva as mensagens de commit no formato [Conventional Commits](https://www.conventionalcommits.org), por exemplo `fix: handle empty course list`. Não adicione `Co-Authored-By`.
4. Rode as verificações que o repositório documenta (testes, linters) antes de abrir o pull request.
5. Abra o pull request contra `main` e preencha o template.

Mudanças chegam ao `main` só por pull request revisado, mesclado com merge commit.
